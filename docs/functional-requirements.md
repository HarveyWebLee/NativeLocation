## 1. 背景与目标

### 1.1 背景

需要一套可安装到 iOS / Android 的定位能力：手机端采集位置，服务端接收并存储，便于后续对接业务系统或外部云服务。

### 1.2 产品目标

1. 用户在手机上安装并打开 App 后，可明确授权定位权限。
2. App 在前台运行时，可持续采集经纬度并实时上报服务端。
3. 服务端校验后将位置点写入数据库，支持按设备查询。
4. 架构预留后台定位与外部云转发，避免后续推倒重来。

### 1.3 成功标准（MVP）

- 真机可完成：注册设备 → 授权 → 开始追踪 → 服务端入库可见。
- 断网短时后可恢复上报（HTTP 批量补传）。
- 前后端共用同一套位置数据契约，字段校验一致。

## 3. 角色与场景

### 3.1 角色

| 角色      | 描述                                      |
| --------- | ----------------------------------------- |
| 终端用户  | 安装 App，授权定位，开启/停止上报         |
| 设备      | 一台物理手机实例，以 `deviceId` 标识      |
| 服务端    | 接收、校验、存储位置数据                  |
| 运维/开发 | 本地启动 DB / API / Metro，查看日志与库表 |

### 3.2 核心用户场景

#### 场景 A：首次打开并开始上报

1. 用户打开 App。
2. App 向服务端注册设备（或读取本地已有 `deviceId`）。
3. 用户可先选采集频率（默认每秒 1 次）。
4. 用户点击「开启定位」。
5. 若尚未授权：先申请「使用期间」前台权限，再申请后台权限；前台授权通过后自动开始采集。
6. 界面显示最近坐标与状态；服务端写入 `LocationPoint`。

#### 场景 B：停止上报

1. 用户在定位中再次点击同一主按钮（文案为「停止定位」）。
2. App 取消定位订阅，断开 WebSocket。
3. 不再产生新上报（本地队列按既有策略处理）。

#### 场景 C：网络不稳

1. WebSocket 断开。
2. App 降级为 HTTP 单点/批量上报，并保留有限本地队列。
3. 网络恢复后优先恢复 WebSocket，并尝试刷出队列。

#### 场景 D：申请或取消定位权限

1. 未授权时按钮为「申请定位权限」：依次申请前台（使用期间）与后台权限；**不**因此自动开始追踪。
2. 已获得前台定位权限时按钮为「取消授权」：打开系统设置，由用户关闭对本 App 的定位授权。
3. 从设置返回或系统对话框拒绝后，若前台权限未授予，**立即停止定位**（取消 watch、断开上报通道）。
4. 后台权限随申请一并请求；MVP **仍不**启动后台 Task 持续上报。

## 4. 功能需求明细

优先级：`P0` 必须 / `P1` 应该 / `P2` 可选（后续）

### 4.1 设备管理

#### FR-DEV-01 设备注册

| 项       | 说明                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 优先级   | P0                                                                                                           |
| 描述     | App 启动时若本地无 `deviceId`，调用注册接口；服务端生成或接受客户端传入的 `deviceId` 并 upsert。             |
| 输入     | `platform`（ios/android/unknown）、可选 `displayName`、可选已有 `deviceId`                                   |
| 输出     | `deviceId`、`platform`、`displayName`、`createdAt`                                                           |
| 验收标准 | ① 首次启动获得稳定 `deviceId`；② 杀进程再开仍使用同一 ID；③ 重复注册不产生重复设备行（按 `deviceId` 唯一）。 |

#### FR-DEV-02 设备本地持久化

| 项       | 说明                                              |
| -------- | ------------------------------------------------- |
| 优先级   | P0                                                |
| 描述     | `deviceId` 保存在端侧持久化存储（AsyncStorage）。 |
| 验收标准 | 卸载前重启 App，`deviceId` 不变。                 |

### 4.2 权限与定位采集

#### FR-LOC-01 定位权限申请与取消

| 项       | 说明                                                                                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 优先级   | P0                                                                                                                                                                                                       |
| 描述     | 独立按钮：未获前台（使用期间）权限时显示「申请定位权限」，依次申请前台与后台权限。已获前台权限时显示「取消授权」，打开系统设置由用户关闭授权（App 无法直接收回系统权限）。拒绝或返回后未授权则停止定位。 |
| 验收标准 | ① 未授权点击申请 → 系统前台权限对话框，允许后再走后台权限；② 已授权按钮文案为「取消授权」并打开设置；③ 用户拒绝或在设置中关闭后停止追踪且无新上报；④ iOS 与 Android 流程均可完成。                       |

#### FR-LOC-02 前台持续采集

| 项       | 说明                                                                                                                                                                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 优先级   | P0                                                                                                                                                                                                                                         |
| 描述     | 使用系统定位能力持续获取位置点，包含经纬度及附属字段。                                                                                                                                                                                     |
| 采集字段 | 见「5. 数据需求」                                                                                                                                                                                                                          |
| 采集策略 | **仅按时间间隔**采样：到点即取当前定位并上报一次，**不因经纬度未变化而跳过**。`recordedAt` 为本次采集时刻（本地时钟），不是 GPS 硬件缓存时间。各端均用定时器 + `getCurrentPositionAsync`（Android 的 `timeInterval` 不能保证静止时回调）。 |
| 验收标准 | 开始后按所选间隔产生新点（经纬度可变可不变）；界面采集时间大致按间隔更新；停止后不再更新。                                                                                                                                                 |

#### FR-LOC-03 开启 / 停止追踪

| 项       | 说明                                                                                                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 优先级   | P0                                                                                                                                                                                        |
| 描述     | 主操作为**一个按钮的两种状态**：未追踪显示「开启定位」，追踪中显示「停止定位」。开启时若无前台权限则先申请前台+后台，前台通过后自动开始。除权限按钮与采集频率选择外，不增加其它操作按钮。 |
| 验收标准 | 开启/停止与 UI、实际上报一致；未授权时点开启会弹出授权且授权后自动追踪；同一按钮可完成启停。                                                                                              |

#### FR-LOC-04 状态可视化

| 项       | 说明                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 优先级   | P0                                                                                                                                                                             |
| 描述     | 界面至少展示：`deviceId`、前台/后台权限状态、运行状态文案、当前采集间隔、最近经纬度、采集时间。服务端 WebSocket JSON（如 ack）须用格式化 JSON 视图展示，禁止单行塞进普通文案。 |
| 验收标准 | 上报成功后采集时间按间隔更新；经纬度未变也须有新点；关键错误有可读文案。                                                                                                       |

#### FR-LOC-05 后台权限（随申请一并请求）

| 项       | 说明                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 优先级   | P1                                                                                                                                 |
| 描述     | 申请定位权限或开启定位时，在前台权限之后请求后台权限。保留后台 Task 占位，**MVP 不自动启动后台更新**。无独立「申请后台权限」按钮。 |
| 验收标准 | 申请流程会触发系统后台权限（若系统允许）；后台未授予时前台追踪仍可进行；未实现持续后台上报亦不崩溃。                               |

#### FR-LOC-07 采集频率

| 项       | 说明                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 优先级   | P0                                                                                                                                                        |
| 描述     | 界面提供采集间隔选项：每秒 2 次、每秒 1 次（默认）、每 3 / 5 / 10 / 15 / 20 秒一次。追踪中更改选项须**立即重启**采集循环，按新间隔采集。不提供每秒 5 次。 |
| 验收标准 | ① 默认每秒 1 次；② 切换选项后新点间隔与所选一致（受系统定位能力上限约束）；③ 追踪中切换无需先点停止。                                                     |

#### FR-LOC-06 后台持续上报（后续）

| 项       | 说明                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 优先级   | P2                                                                          |
| 描述     | App 退至后台或锁屏时仍可按策略采集并上报，并满足系统前台服务/后台模式要求。 |
| 验收标准 | Phase 2 单独验收（耗电、系统限制、审核文案）。                              |

### 4.3 上报与通信

#### FR-UP-01 WebSocket 实时上报

| 项       | 说明                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| 优先级   | P0                                                                                      |

#### FR-UP-02 HTTP 兜底上报

| 项       | 说明                                                            |
| -------- | --------------------------------------------------------------- |
| 优先级   | P0                                                              |
| 描述     | WS 不可用时，通过 `POST /v1/location/batch`（或单点接口）上报。 |
| 验收标准 | 断开 WS 后仍可入库；网络恢复后可切回 WS。                       |

#### FR-UP-03 本地缓冲队列

| 项       | 说明                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 优先级   | P1                                                                            |
| 描述     | 上报失败或短暂断线时，端侧保留有限环形队列（如上限 100 条），恢复后尝试刷出。 |
| 验收标准 | 短时断网再恢复，队列内点可被补传或明确丢弃策略可观测。                        |

#### FR-UP-04 上报节流与过滤

| 项       | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 优先级   | P1                                                           |
| 描述     | 采集侧已按用户选择的时间间隔采样；上报不再叠加位移阈值过滤。 |
| 验收标准 | 静止时上报频率不超过所选采集间隔（受系统回调上限约束）。     |

## 5. 数据需求

### 5.1 LocationPoint（逻辑字段）

| 字段       | 类型                | 必填         | 说明                    |
| ---------- | ------------------- | ------------ | ----------------------- |
| deviceId   | string              | 是           | 设备唯一标识            |
| latitude   | number              | 是           | WGS84 纬度，[-90, 90]   |
| longitude  | number              | 是           | WGS84 经度，[-180, 180] |
| accuracy   | number              | null         | 否                      | 水平精度（米）           |
| altitude   | number              | null         | 否                      | 海拔（WGS84 椭球高，米） |
| speed      | number              | null         | 否                      | 速度                     |
| heading    | number              | null         | 否                      | 航向                     |
| recordedAt | ISO datetime string | 是           | 采集时间（端侧）        |
| source     | `foreground`        | `background` | 是                      | 默认 foreground          |

服务端额外字段：

| 字段       | 说明           |
| ---------- | -------------- |
| id         | 主键           |
| receivedAt | 服务端接收时间 |

### 5.2 Device

| 字段                  | 说明                    |
| --------------------- | ----------------------- |
| deviceId              | 唯一                    |
| platform              | ios / android / unknown |
| displayName           | 可选                    |
| createdAt / updatedAt | 审计时间                |

### 5.3 查询需求（MVP）

- 按 `deviceId` + 时间倒序查看最近轨迹点（索引支持）。
- MVP 可不提供对外查询 HTTP API（可用 Prisma Studio / SQL）。

## 6. 接口需求摘要

| 方法 | 路径                   | 说明     | 优先级 |
| ---- | ---------------------- | -------- | ------ |
| GET  | `/health`              | 健康检查 | P0     |
| POST | `/v1/devices/register` | 设备注册 | P0     |
| POST | `/v1/location/point`   | 单点上报 | P0     |
| POST | `/v1/location/batch`   | 批量上报 | P0     |
| WS   | `/v1/location/stream`  | 实时上报 | P0     |

错误约定：

- HTTP：非法 body → `400`，附带校验详情。
- WS：返回 `{ type: 'error', message, details? }`；成功 ACK：`{ type: 'ack', inserted, deviceId, recordedAt }`。

契约唯一来源：`packages/shared`。

## 8. 权限与合规文案（要求）

### 8.1 iOS

- `NSLocationWhenInUseUsageDescription`：使用期间定位说明。
- `NSLocationAlwaysAndWhenInUseUsageDescription`：后台能力预留说明。
- 若启用后台：`UIBackgroundModes` 含 `location`。

### 8.2 Android

- 前台：`ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION`
- 后台预留：`ACCESS_BACKGROUND_LOCATION` 及前台服务相关权限（启用后台时）

文案需中文、可读，说明「用于实时上报位置 / 持续追踪（若后台）」。

## 9. 异常与边界

| 场景                   | 期望行为                                           |
| ---------------------- | -------------------------------------------------- |
| 用户拒绝前台定位       | 不追踪；若正在追踪则立即停止；UI 提示未授权        |
| 用户在系统设置关闭定位 | 回到 App 后检测权限，未授予则停止追踪              |
| 定位超时/无信号        | 不伪造坐标；可提示定位失败                         |
| API 不可达             | 设备注册失败有明确错误；追踪时走队列/HTTP 失败提示 |
| 非法坐标               | 服务端拒绝，不入库                                 |
| 批量超过 200           | 拒绝整包或部分策略需在实现中固定为「拒绝整包」     |
| App 被系统杀死         | 前台追踪停止；重启后需用户再次开始（MVP）          |
| Expo Go SDK 不匹配     | 无法加载项目；文档要求 SDK 与 Expo Go 对齐         |

## 10. 分期计划

### Phase 1 — MVP（当前）

- 设备注册、前台定位、可配置采集间隔、WS/HTTP 上报、PostgreSQL 落库、Tamagui UI、申请时附带后台权限（Task 仍预留）。

### Phase 2 — 后台与稳健性

- 后台持续定位、省电策略、更完善离线队列与重试、用户登录。

### Phase 3 — 业务扩展

- 外部云转发 Adapter、轨迹查询 API、地图回放、账号体系、管理端。

## 11. 验收清单（MVP）

- [ ] 停止后不再新增点（短延迟内）
- [ ] 断开 WS 时 HTTP 兜底仍可入库（可测）
- [ ] `/health` 返回正常
- [ ] 非法 payload 被拒绝
- [ ] 申请流程会请求后台权限且不导致崩溃（可不真正开启后台追踪）

## 12. 术语

| 术语          | 含义                                                       |
| ------------- | ---------------------------------------------------------- |
| 前台定位      | App 在前台时的定位采集                                     |
| 后台定位      | App 不在前台时仍采集（本期仅预留）                         |
| LocationPoint | 单次位置采样记录                                           |
| deviceId      | 设备业务主键，端侧与库一致                                 |
| WGS84         | 国际 GPS 经纬度标准；本产品 iOS/Android 采集与入库均为此系 |
